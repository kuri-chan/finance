# 手取りラボ｜運用スキーム体系図

> 「診断プロダクト × アフィリ収益 × SNS/SEO集客」を、8つの定期タスクとSlack承認で回す仕組みの全体像。
> **あなたが手を動かすのは、原則Slackでの承認だけ**に設計されている。
> ビジュアル版（Artifact）：https://claude.ai/code/artifact/e9f9eec0-f0e9-4203-a1c9-0bfadf407463
> 最終更新：2026-08-15

**凡例**：🟢稼働中／🟠準備中・要調整／🟣あなたの対応／⚪全自動

---

## 1. 価値の流れ（3ブロック）

集客で人を発見し → プロダクトで価値提供し → アフィリで収益化する（左→右）。この輪が回るほどSEOとカード拡散の複利が効き始める（＝コールドスタート脱出）。

```
[01 集客（発見）]  →  [02 プロダクト]  →  [03 収益]
```

| ブロック | 中身 |
|---|---|
| **01 集客（発見）** | 🟢Threads（主軸・累計約7.1万閲覧）／SEO記事55本（検索の複利）／リプ営業（0→最初の種）／X（リプ専用に降格）・note（週1） |
| **02 プロダクト（手取りラボ）** | 保険・ふるさと・iDeCo・NISA・住宅を横断 →「改善余地◯円＋効果額順の打ち手」／診断結果シェアカード＝拡散資産／Next.js・Vercel・GA4 |
| **03 収益（アフィリ）** | 🟢保険相談（主砲）・火災・NISA・iDeCo／記事末＋診断結果に自動でCTA点灯／🟠自動車・ふるさと納税は準備中／成果報酬型（サブスクなし） |

## 2. 自動化パイプライン（定期タスク8本）

時刻はJST。cronは各時刻ちょうどに設定しているが、システムが**負荷分散のため数分の遅延を必ず付与**する（外せない）。承認はすべて **Slack DM** に集約。

### トラックA：リプ営業ループ（発見エンジン）
生活者の投稿にリプ → プロフ流入 → フォロー。

| タスク | スケジュール | 内容 | 担当 |
|---|---|---|---|
| `sns-reply-research` | 毎日 08:00 / 21:00 | Threads中心に生活者の投稿をリサーチし、URL付きリプ案をSlackへ | 🟣承認→あなた |
| `sns-reply-approval-executor` | 8–9時・21–22時に15分ごと | 承認窓（research実行後1時間）だけ稼働。Slackで承認済みのリプ案を検知したらすぐ実投稿＋いいね。窓外に承認しても投稿されない＝鮮度の落ちたリプは出さない規律 | ⚪全自動（承認後） |

### トラックB：週次投稿ループ（X／Threads本体）
1週間分を自動下書き → 承認 → 予約投稿 → ツリー化。

| タスク | スケジュール | 内容 | 担当 |
|---|---|---|---|
| `sns-weekly-draft-generator` | 日 18:00 | 月〜土のX/Threads投稿を各プラットフォーム下書きに保存＋**土20:00公開のnote記事1本**を`content/note-drafts/`に生成し、Slackへ承認依頼（noteは手動公開） | 🟣承認→あなた |
| `sns-draft-approval-checker` | 日 18–23時 毎時 | 承認を検知したら下書きを予約投稿にセット | ⚪全自動（承認後） |
| `sns-draft-approval-reminder` | 月 08:00 | 未承認ならリマインド（承認済みなら予約もセット） | ⚪全自動 |
| `sns-x-thread-followup-poster` | 18–23時 2分ごと | Xの予約が公開されたら3分以内に追いリプしてツリー化 | ⚪全自動 |

### トラックC：学習ループ（戦略の自己更新）
「内容の振り返り（毎週・定性）」と「軌道の振り返り（隔週・定量）」の2階層。

| タスク | スケジュール | 内容 | 担当 |
|---|---|---|---|
| `sns-trend-research` | 土 09:00 | ①自分の直近投稿の勝ち筋を分析 ②他者の高反応事例をリサーチ → `[翌週反映]`タグ付き示唆をSlack/playbookへ → 翌日の下書き生成が取り込む | ⚪全自動 |
| `sns-metrics-review` | 毎月 1日・15日 10:00 | SNS数値を集計し前回比Δ＋変換率（閲覧→送客→診断到達）を算出。台帳（`docs/sns-metrics-log.md`）に追記し「次の1手」をSlackへ。GA4はSlackで補完依頼 | 🟣GA4数字の補完（あれば） |

## 4. あなたが対応する事項

日常はSlackの承認2種だけ。あとは前提づくりと、承認連絡が来たときの都度対応。

### 🟣 毎日／毎週：Slackでの承認（これが本業）
- [ ] **リプ案の承認** — 朝8時・夜21時に届く。OKを出したものだけ15分以内に自動投稿。却下・修正もSlackで。
- [ ] **週次投稿ドラフトの承認** — 日曜夜に1週間分が届く。承認すると予約投稿化 → 自動でツリーまで組む。月曜朝に未承認リマインド。

### 🔵 前提（一度／維持）：タスクが動く環境を保つ
- [ ] **実行3条件** — ① Macが起きている ② Claude Code起動中 ③ ChromeがX/Threadsにログイン済み。この3つが揃った時刻にだけタスクは走る。
- [ ] **スリープ抑止** — `システム設定 › バッテリー › 電源アダプタ` で「ディスプレイOFF時もスリープさせない」をON。MacBookはフタを開けたまま＋電源接続。寝てても実投稿は承認式なので取りこぼしは軽微。

### 🟣 隔週：GA4の数字を貼る（1日・15日）
- [ ] **スコアカードの「要入力」に回答** — `sns-metrics-review`がSlackで聞いてくる分だけ（Organic Social／SNS新規ユーザー／`/diagnose`到達／アフィリクリック）をGA4から貼る。UIから自動取得できた回は不要。所要2分。

### 🟠 都度：アフィリ承認が来たら私に連携
- [x] **ふるさと納税：ふるなび（アクセストレード）承認・接続済み（2026-08-20）** — Q4商戦に向けライブ化。残るは2枚目のふるさとチョイス（VC審査待ち）の承認連絡のみ。
- [ ] **自動車保険：代替ASPの目星** — インズウェブが承認落ち。価格.com／楽天／NTTイフ等を申請 → 通ったら連携。
- [ ] **再申請の余地（サイト成長後）** — SBI証券・さとふるは一度承認落ち。記事・流入が増えたタイミングで再申請の価値あり。

### ⚪ 節目：マイルストン・法務
- [ ] **指標の再計測：8/27ごろ** — Threads閲覧数・X閲覧数・GA4 Organic Social・`/diagnose`到達を再取得し、導線改善の効果を確認。**＝増量（週7・1日2投稿）解禁ゲートAの判定日**（送客率0.01%→0.3%+か。詳細は`sns-growth-playbook.md`§9.6）。
- [ ] **勤務先への副業申請** — 申請制のため。匿名運用・本業（予防医療toG）と明確に分ける前提。
- [ ] **商用化時：特商法・運営者情報** — メール取得など収益導線が進んだら、屋号＋最低限の法定表記を用意（着手時に確認）。

> **要するに：** 仕組みは「リサーチ→案→**あなたの承認**→自動投稿」で回る。日常負荷は **Slackの承認2種** のみ。残りは環境維持と、アフィリ承認が来たときの都度連携。
