# SNS運用戦略（X / Threads / note）— フォロワー→診断→アフィリ

> 目的：広告ゼロで、フォロワーを増やし、**診断してもらう人数を最大化**し、アフィリ成果につなげる。
> 併読：`docs/distribution-strategy.md`（全体）／`docs/x-content-pack.md`（X弾）／`docs/note-content-pack.md`（note弾）。
> 遵守：情報提供・シミュレーション（募集/助言でない）／資格匂わせない／断定・銘柄推奨しない／SNSに直アフィリは貼らない／PR明示／旧社名なし・顔出しなし。
> 最終更新：2026-08-03

---

## 0. ファネル（これが全て）

```
発見（X/Threads/note/検索）
  → フォロー・関心（“元保険営業の本音×売らない”で信頼）
  → サイト来訪（記事 or 診断）
  → ★診断実行（KPI①：収益の入口）
  → 打ち手のPR導線クリック（KPI②）
  → アフィリ成果（KGI）
```
**フォロワーは中間指標。勝負は「診断到達数」。** バズより、診断に来る質の高い接点を積む。

## 1. チャネル役割マトリクス

> **2026-08-13改訂**：立ち上げ1週間の実績（`sns-growth-playbook.md`§8）で、Threads累計閲覧 約71,000回 に対し X は全11投稿で合計100強・いいね0という非対称が判明。**主軸をXからThreadsに入れ替え**、Xはリプ営業中心に軽量化。noteは計画未達（週1→実質1本のみ）だったため頻度を死守すべき列に格上げ。

| | **Threads（主軸）** | **X（補完・リプ営業中心）** | **note（ストック）** |
|---|---|---|---|
| 型 | フロー・低工数・実測でリーチが出ている | フロー・拡散（実績は現状薄い） | ストック・検索・ファン化 |
| 長さ/文体 | 短文・会話/共感寄り | 短文・言い切り | 長文・思想/体験 |
| 主コンテンツ | 会話調の本音・問いかけ・数字フック | リプ営業（`sns-reply-playbook.md`）中心、投稿は最小限 | 創業ストーリー／裏側／体験 |
| 強み | 実測で唯一送客できているチャネル | リプ経由の発見導線としては維持価値あり | SEO・被リンク・深い信頼 |
| 頻度 | **毎日1本＋固定ポストのCTA改善** | **投稿は週2〜3本に減らしてOK／リプは継続** | **週1本（死守）** |
| 主目的 | 診断送客（実測ベースで最優先） | 発見・関係構築（投稿より会話重視） | 検索流入＋ファン化＋被リンク |

**使い分けの原則**：ネタは1つ、器で変える。
- 例）「独身に大きな死亡保険はいらない」
  - X＝言い切り1ポスト＋データ＋記事/診断リンク
  - Threads＝「これ、意外と知られてないけど…」と会話調で問いかけ
  - note＝保険営業時代の体験を交えた長文エッセイ→診断へ

## 2. 投稿頻度と週次リズム（週13時間の現実解）

- **X**：平日は本音ポスト1＋リプライ数件／新記事公開日はスレッド。週末は軽め。
- **Threads**：Xの当日ポストを微調整して1本（工数ほぼゼロ）。
- **note**：週末にまとめ書き→月2〜4本ペース。
- **バッチ作成**：実弾開始後は「週次で下書き自動生成（Claude）→ 予約投稿ツールで配信」（後日セットアップ）。

## 3. コンテンツの5分類（ネタが尽きない型）

1. **本音（権威×逆張り）**：保険の内側から見た“要らない保険”。最もフォローを生む。
2. **教育（1テーマ1分）**：高額療養費／ふるさと納税の枠／iDeCoの落とし穴。保存されやすい。
3. **速報（制度スパイク）**：改正・年収の壁が話題化した当日に解説。フォローの瞬間最大化。
4. **体験・思想**：なぜ売らないか、診断ロジックの裏側（主にnote）。ファン化。
5. **企画・参加型**：診断結果のシェア文化／アンケート／質問。バイラルループ。

## 4. フォロワー獲得の具体戦術（X中心）

1. **プロフィール＆固定ポストの最適化**：「フォローする理由」を一目で（元保険営業の本音×売らない×無料診断）。→ `x-content-pack.md`
2. **本音×数字×言い切り**：一般論として言い切る勇気（※個別断定・銘柄推奨はしない）。「〜な人が多い」「基本いらない」等は保存・引用されやすい。
3. **リプライ戦略（最重要）**：新婚・共働き・お金系の大型アカウントへ、**宣伝でなく“価値あるリプ”**（知見を足す）。ここで発見される。1日数件。
4. **制度スパイク速報**：改正日にいち早く解説。伸びる瞬間を取りにいく。
5. **参加型企画**：「うち世帯、年◯万円の改善余地だった」を晒す文化（結果カードのシェア）＝他人も試したくなる。
6. **継続と時間帯**：朝(7-9時)・夜(21-23時)。毎日の積み重ね＞一発バズ。
7. **相互交流**：同ジャンルのクリエイターと関係構築（引用・コラボ）。
8. **Threads早期参入**：新興プラットフォームは初速でリーチが出やすい。Xと同時運用で取りこぼさない。

## 5. 「診断してもらう」ための送客設計

- **ソフトCTA**：全ポスト末尾にリンクを貼らない。**3投稿に1回**くらい自然に「自分はどう？→無料診断」。押し売り感を避ける（＝売らないブランド）。
- **常設導線**：プロフィールのリンク＝サイト、固定ポスト＝診断へ。
- **バイラルループ**：診断結果カード（X/LINEシェア実装済）→ `/r` がOGで展開 → クリック → 診断 → 再シェア。SNS投稿で「あなたは？」と促す。
- **記事→診断**：教育ポストは該当記事へ、記事末は診断へ（既に全記事に設置済み）。

## 6. アフィリにつながる導線（現状）

診断結果のPR導線が収益源。**現在ライブ：iDeCo・NISA（松井）／ふるさと納税（ふるなび）／火災保険**。→ 診断に来てもらえれば、この4つは今すぐ収益化する。主砲・保険相談（保険コンパス）は承認待ち。
> つまり「診断到達を増やす」＝そのままアフィリ成果に直結する状態。

## 7. KPIツリーと計測（GA4）

- **KGI**：アフィリ成果（円）
- **KPI①：診断到達数**（GA4：social参照元 →`/diagnose`）← 最重要
- **KPI②：PR導線クリック**（`/r`・アフィリリンクのクリック）
- 先行指標：フォロワー増・エンゲージ・プロフクリック（虚栄指標に注意。診断到達に相関するかで判断）
- 月次で「どのチャネル/どの投稿が診断到達を生んだか」を見て、翌月の配分を決める。

## 8. 90日ロードマップ

- **Month1（土台）**：X毎日投稿＋固定ポスト、note創業ストーリー、Threads再利用開始。リプライで接点作り。“存在”を作る期間（フォロワー数に一喜一憂しない）。
- **Month2（伸ばす）**：どの本音が刺さるか検証、制度スパイク狙い、結果シェア企画、note月2〜4本。GA4で診断到達を確認。
- **Month3（最適化＆自動化）**：反応の良いテーマを記事化（SEOへ還元）、上位ポストを再利用・固定差し替え、診断到達の多い流入に集中。**週次の下書き自動生成（Claude）を導入**。

## 8.5 自動化パイプラインと承認フロー（2026-08-13構築）

`sns-weekly-draft-generator`（週次投稿ドラフト）／`sns-reply-research`（リプ営業案）は、いずれも**作成のみで実行はしない**。実行は「承認」を検知した別タスクが担う。

- **承認経路は2つ、併用可**：
  1. **Slack**：スレッドに「承認」と返信 → バックグラウンドタスクが検知して実行（週次投稿は日曜18-23時に毎時チェック＋月曜8時に最終チェック/リマインド、リプ案は15分ごとにチェック）。タイムラグあり（最大15分〜数時間）が、スマホからどこでも承認できる。
  2. **Claude Codeのチャット**：ユーザーが直接「承認して」と伝える → その場で状態ファイル（各タスクの`state.json`）を見て即実行。タイムラグ無しだが、Claude Codeを開いて能動的に伝える必要がある。
- 状態ファイルの場所：`~/.claude/scheduled-tasks/sns-weekly-draft-generator/state.json`／`~/.claude/scheduled-tasks/sns-reply-research/state.json`。
- 承認ワードは「承認」固定（誤検知を避けるため部分承認は非対応、全件承認のみ）。
- **Slackチャンネル分け（2026-08-14〜）**：以前は全てDM通知だったが、内容ごとに分離。`#sns-投稿`（C0BQ3JM9B9C＝週次ドラフト系）／`#sns-リプ`（C0BPQ6N8955＝リプ営業系）／`#sns-リサーチ`（C0BQ7FY1U8Z＝トレンドリサーチ）。
- **Xのツリー予約は不可（2026-08-14実機検証で判明）**：Xで「+」複数投稿を組んでから予約設定すると内容が失われる不具合がある。Threadsは「スレッドに追加」のツリーごと正常に予約できる。そのため**Xは本体のみ単発で予約し、補足（リンク誘導など）は本体公開後に`sns-x-thread-followup-poster`（30分ごとチェック）が自動で追いリプする**設計にした。Xでリンクを本文に直接置くとアルゴリズム上リーチが落ちるため、リンクは追いリプ側に置く方針も兼ねている。
